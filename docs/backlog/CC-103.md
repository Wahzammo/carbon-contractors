# CC-103 — x402 survives only as stale references

## Problem

`CC-081` (closed 2026-08-21) removed x402 as the escrow funding mechanism, and that was the
**only live x402 usage in the product**. Verified 2026-09-08 against the current tree:

- **No route emits a 402.** `grep -rn "status.*402|paymentRequired" src/app` → zero hits.
  No endpoint asks for payment, so there is no per-call billing layer of any kind. The MCP
  tools are free; the only money in the product is the escrow path (agent-funded
  `createTask`, worker payout, staking), which uses plain wallet-to-contract calls.
- **No route imports the x402 wrapper or client.** `withX402` is gone (CC-081 Defect 1);
  `src/lib/x402-client.ts` has no caller outside its own tests.
- **`/mcp-info`** — the page that teaches agents the platform — does not mention x402.

What survives is stale:

1. **Homepage / coming-soon copy** (`src/components/ComingSoon.tsx`, `src/components/HomePage.tsx`):
   an "x402 protocol" bullet advertising a protocol the product does not use.
2. **`/learn` curriculum** (`src/lib/learn/modules.ts`, `src/app/learn/page.tsx`): references the
   x402 flow; the product's funding flow is `USDC.approve` + `escrow.createTask` +
   `POST /api/fund-task` confirmation.
3. **Dead code:** `src/lib/x402-client.ts` is a circuit breaker (NOR-182) built to protect
   facilitator calls that no longer exist. `src/lib/payments/x402.ts` carries vestigial naming —
   `initiateX402Payment` (takes no payment; its own header says so), `replayX402Payment`,
   `X402PaymentRequest` — kept "for import compatibility."
4. **`src/app/robots.ts`** references x402 (minor, same sweep).

## Decision needed (PO) — is x402 coming back?

The homepage bullet may have been forward-looking rather than descriptive. Two branches:

- **x402 returns as agent-side billing post-launch.** Then this ticket shrinks to: keep the
  bullet, update `/learn` to teach *both* flows (billing vs escrow funding — the CC-081 lesson
  is that conflating them is how Defect 1 happened), and keep the dead code until the billing
  layer lands. Record the decision in this ticket and link the future billing ticket here.
- **x402 does not return.** Then: remove the homepage bullet (replace with the honest list —
  USDC, Base, non-custodial escrow), rewrite the `/learn` modules to the actual funding flow,
  delete `x402-client.ts` and its tests, and rename the survivors in `x402.ts`
  (`initiateX402Payment` → something that doesn't promise payment) with their call sites in
  `src/lib/mcp/server.ts`.

Either way: `/learn` must not teach a flow the product doesn't run — that is the same
copy-vs-reality drift that `CC-081`'s self-contradicting `x402.ts` embodied.

## Acceptance

- [ ] PO decision recorded (return vs retire) in this ticket.
- [ ] No public copy or `/learn` module references x402 unless the product actually uses it.
- [ ] If retiring: `x402-client.ts` deleted, `x402.ts` naming de-x402'd or module renamed,
      tests updated, `npm test` green.
