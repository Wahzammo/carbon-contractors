# CC-104 — Invariant monitor alert semantics

## Problem

PO report 2026-09-09: "invariant monitoring failures left, right and centre." Forensic
decode of the last 100 scheduled `monitors.yml` runs (32 failed) found **zero actual
invariant breaches**. Every red run decomposed into:

1. **TRAN (transport)** — `verify-unclaimed` / `verify-concurrent-escrow` exhausting RPC
   retries against the **public rate-limited endpoint**. The workflow references
   `BASE_SEPOLIA_RPC_URL` as a secret, but **that secret does not exist in the repo**
   (verified: only MONITOR_HEARTBEAT_URL, MONITOR_WEBHOOK_URL, SUPABASE_URL,
   SUPABASE_ANON_KEY are set), so every hourly run rides the fallback CC-048 warned
   about. The two failing monitors are the two doing heavy `getLogs` scans.
2. **SKIP (permanent)** — `verify-eas-schema` has SKIPped **every run since 2026-08-31**:
   `EAS_SCHEMA_REGISTRY_ADDRESS` was never wired into the workflow env. The address is a
   public OP-Stack predeploy recorded in the repo's own `chain-constants.json`
   (`0x4200000000000000000000000000000000000020`). Verified 2026-09-09: with the env var
   set, the monitor **passes** (uid, schema string, resolver, revocable all confirmed
   against Base Sepolia).
3. **CONF (historical)** — `Position 415 out of bounds` on `verify-unclaimed`,
   2026-08-28→29: the CC-082 redeploy window, resolved by the CC-070 deploy-block
   re-derivation. Does not recur.

The first-principles flaw: `ADR-0003`'s own thesis is alert quality ("an alert channel
nobody reads is not an alert channel"), and the runner honours it with a five-way result
taxonomy (PASS/FAIL/CONF/TRAN/SKIP) — but the alert layer then **flattened TRAN, CONF and
FAIL into one webhook message** whose fixed footer said "First response is to PAUSE NEW
TASK CREATION" (ADR-0003 D4). An RPC blip paged with the nuclear response for a solvency
breach. That is alert fatigue arriving from exactly the direction the ADR warned about.

## Changes

1. **`scripts/audit/alert-classify.mjs`** (new) — pure, tested classification:
   `breach` / `misconfig` / `unchecked` / `green`, worst-wins, and per-class alert
   bodies. Breach keeps pause-intake guidance (ADR-0003 D4) and now also names any
   monitors that went unchecked *during* the breach. Misconfig says "fix the config, not
   the chain". Unchecked says "transport, not a breach; no pause required for a single
   occurrence; sustained TRAN is investigated per runbook §6".
2. **`scripts/audit/run-monitors.mjs`** — sources classification + body from the module
   (same extraction pattern as `verdict-line.mjs`); prints a `class:` summary line so one
   shade of Actions red is decodable without opening the log; exit codes unchanged
   (TRAN/CONF still non-green per D3 — an unchecked invariant is not a passing one).
3. **`.github/workflows/monitors.yml`** — `EAS_SCHEMA_REGISTRY_ADDRESS` wired inline as a
   public constant (same convention as the contract addresses; the workflow's own header
   explains why public facts are not secrets).
4. **`docs/runbooks/INVARIANT-ALERTS.md`** — new §0 class table (what the first line of
   an alert means, and when the kill switch applies), §5 (misconfig response), §6
   (transport response incl. the `BASE_SEPOLIA_RPC_URL` check); resumption gate updated
   from the stale "5/5" to "class green, zero SKIP".
