# CC-106 — Required status check on `build`

## Problem

Observed 2026-09-09: PR #201 auto-merged while its `build` check was failing (the
security-audit step, red from advisory-DB drift — see `CC-105`). The merge was correct
*that* time, but only by luck of the diagnosis: nothing in branch protection requires
`build` to pass before a merge, so a PR carrying a **real** regression could merge the
same way, unreviewed by CI.

This is a repo-settings change (Settings → Branches → Branch protection for `master` →
Require status checks to pass → tick `build`). It needs the account owner; it cannot be
done from a token that lacks admin scope on repo settings, and it should not be done
blindly while a PR is mid-flight — do it when no PRs are open.

## Acceptance

- [ ] `build` listed as a required status check on `master` branch protection
- [ ] Verified: a PR with a failing `build` cannot merge (can be asserted from the
      protection rule itself; no need to deliberately break CI)
